Drawing and Performance

The Draw() function usually performs a lot of work and is called very often, every time when a chart needs to be repainted (and this happens every time when any object on the chart is added, changed or removed, when window is activated or deactivated, when its size or position is changed and just when the operating system decided that it is time to repaint a window.

So, any performance problem in this function will dramatically affect the performance of the whole application. Please follow recommendations below to improve the performance of the Draw() function.

1) Never, never do any data calculations in the Draw() function. Prepare any data to be displayed in Update() and AsyncOperationFinished() functions of the indicator. These functions are called when the context of the indicator may be changed, so these calculations will be performed when they are supposed to be performed.

2) Load images and create fonts as seldom as it is possible. Avoid creating these objects at every call of the draw function. Once created, any tool remains in the context until it is destroyed or the indicator is removed from the chart, so you can save a lot of time performing these operations only once.

3) If you use a few number of the pens and brushes, create them once too.

4) Avoid using transparency parameter of the drawing methods unless you really-really need the transparency for your drawing. It may look cool, but this is not enough to introduce very slow operation into your drawing process.

5) Use the startEnumeration() and nextBar() methods of the context if you need to draw something for each bar visible on the chart. These operations greatly optimizes the performance for high-zoom charts, especially when the chart displays more bars than the chart has pixels (i.e. 300,000 bars on 1000 pixels chart). This enumeration will return you only those bars which are actually displayed by the chart application itself and will help you to avoid drawing the bars which aren't actually displayed because the chart is too condensed.

6) Polygons and Bezier Shapes are pretty slow when the number of points is big (hundreds of points). Avoid using complex shapes.
